Отдельное локальное приложение от DysseuX / DysseuX Group. Два снимка ушей,
разметка линейки и размеры головы → экспериментальный персональный SOFA.
Приложение не обучает нейросети, не отправляет фотографии и не требует
плеера для создания профиля. Готовый SOFA можно импортировать в exstereo.

Язык интерфейса выбирается автоматически по первому языку в системном
списке Android: `ru` → русский, любой другой → английский. Ручного
переключателя нет. Версия 0.2.0 добавляет локализацию; модели и расчёт
профиля сохранены.

## Использование

1. Выберите фото каждого уха или запустите системную камеру из приложения.
   Снимайте строго сбоку, при ровном освещении, без закрывающих ухо волос.
   Линейка должна быть рядом и в той же плоскости. Попросите другого человека
   помочь со съёмкой; оставьте поле вокруг уха для квадрата 9,5 × 9,5 см.
2. В окне разметки можно увеличить, уменьшить и сдвинуть фото под условный силуэт уха.
   Силуэт можно отключить; он не меняет фото и не подаётся в модель.
   Отметьте слуховой проход и два деления линейки, введите расстояние в мм.
3. Проверьте контуры. Регулируйте порог; для правого уха по умолчанию задано
   отражение. Если снимок уже зеркальный, проверьте ориентацию вручную.
4. Укажите ширину головы над ушами и глубину от лба до затылка в сантиметрах.
   Требуются прямые размеры, а не обхват головы.
5. Создайте профиль. Расчёт выполняется одним рабочим потоком CPU; его можно
   отменить. Во время работы приложение удерживает экран включённым.
6. Сохраните `personal.sofa` через системный выбор места. В exstereo откройте
   «Звук в наушниках» → настройка HRTF → «Импортировать SOFA с ПК».
   Несмотря на название пункта, он принимает и файл, созданный на телефоне.

После изменения входных данных профиль нужно создать заново. Экспорт всегда
сохраняет последний успешно завершённый результат. Отмена не заменяет его.
Внутренние фото, разметку и профили можно удалить отдельной кнопкой. Исходники
в галерее и ранее экспортированные файлы эта кнопка не удаляет.

## Модели и границы метода

Используется закреплённая ITSADIVE из соседнего `kubuntu-hrtf`: Inception
encoder и mean latent, затем DNN и декодер CVAE. Только FP32 inference,
без случайного семплирования, обучения, PyTorch и Python на Android.
Мобильные файлы занимают **16 016 435 байт** вместо **75 922 584 байт**
исходных checkpoint. Удалены image decoder VAE, encoder CVAE, состояние
обучения и другие неиспользуемые части. Исходная ПК-программа сохранена.

Автоматические контуры не являются анатомической сегментацией. Сеть оценивает
ушные фильтры приближённо; акустическая стадия добавляет универсальную голову
VIKING, минимально-фазовые FIR и аналитические задержки по размерам головы.
Это не акустическое измерение человека. Частотная калибровка и ограничения
исходного исследовательского прототипа остаются; улучшение относительно
KEMAR/SADIE не гарантируется. Оценивать результат нужно прослушиванием.

Выход: SOFA SimpleFreeFieldHRIR, 48 кГц, 729 направлений, два уха,
2200 отсчётов на импульс. Задержки включены в Data.IR, Data.Delay = 0.
Фиксированный хвост содержит нули; размер позволяет все разрешённые размеры
головы. SOFA содержит атрибуцию VIKING/ITSADIVE. Даты внутри шаблона относятся
к его выпуску; фактическая дата расчёта, размеры и SHA находятся в report.json.

## Совместимость

- Android 8.0 / API 26 и выше, 64-битный ARM (arm64-v8a).
  В APK для телефона нет второй копии движка для x86-эмулятора.
- CPU достаточно для расчёта; NPU/GPU не обязательны.
- APK не запрашивает интернет, доступ ко всей галерее или разрешение камеры:
  выбор файлов и съёмку выполняют системные приложения с временным доступом
  к конкретному файлу.
- Фото до 32 МиБ; перед разметкой длинная сторона ограничивается 1600 пикселями,
  ориентация EXIF применяется, исходные EXIF в копию не переносятся.
- Скорость, камера и расход памяти на физическом телефоне пока не проверены.
  JVM-проверки с настоящим ONNX Runtime не заменяют запуск на Android.

## Сборка и воспроизводимость

Готовые модели и SOFA-шаблон уже включены. Для обычной сборки достаточно
`bash build-limited.sh :app:testDebugUnitTest :app:assembleDebug` из `android-hrtf`.

Для пересоздания моделей и шаблона — из корня всего проекта.
Для экспортов нужно отдельное Python 3.12 окружение;
портативный HRTF setup не меняет Torch/torchaudio Demucs:

```bash
XDG_DATA_HOME="$PWD/android-hrtf/.runtime" SPATIAL_BASE_PYTHON=python3.12 bash kubuntu-hrtf/setup.sh --android-export
XDG_DATA_HOME="$PWD/android-hrtf/.runtime" SPATIAL_BASE_PYTHON=python3.12 bash kubuntu-hrtf/launch.sh --tool android-hrtf/tools/export_models.py
XDG_DATA_HOME="$PWD/android-hrtf/.runtime" SPATIAL_BASE_PYTHON=python3.12 bash kubuntu-hrtf/launch.sh --tool android-hrtf/tools/export_reference.py
cd android-hrtf
bash build-limited.sh :app:testDebugUnitTest :app:assembleDebug
```

Wrapper использует обязательную точку входа `android-player/build-limited.sh`,
но выбирает отдельный проект и пропускает сборку плеера. Все тяжёлые операции
остаются под общим `scripts/run-limited.sh`: CPU 210% на трёх доступных ядрах,
RAM 3 ГиБ, без swap, одна операция и последовательные тестовые процессы.

ONNX Runtime Android закреплён на 1.24.3. Лицензии ITSADIVE MIT, VIKING
CC BY 4.0, ONNX Runtime MIT и сторонних компонентов включены в приложение.
Полные checkpoint, desktop Python и тестовые фотографии в APK не включаются.

`tools/verify_release.py` проверяет готовый APK, результаты тестов, ограничения
cgroup и реальные SOFA через netCDF4 и libmysofa, затем сохраняет выпуск в
`../artifacts/hrtf-photo-v2.apk`. Запускать после сборки через тот же портативный
HRTF launcher с `--tool android-hrtf/tools/verify_release.py` из корня проекта.
Для этой проверки на ПК нужна системная `libmysofa.so.1`.
