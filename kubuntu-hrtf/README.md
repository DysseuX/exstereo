# Spatial HRTF

Экспериментальное приложение для Kubuntu/Linux: фотографии двух ушей и размеры
головы → контуры → предобученные сети ITSADIVE → профиль `personal.sofa`.
Обработка выполняется локально. Фотографии никуда не отправляются.
Результат — расчётное приближение HRTF, а не акустическое измерение.

## Установка и запуск

Нужны Python 3.11+, модуль Tk, `venv` и работающий пользовательский сеанс
systemd с cgroup. Сохраняйте соседний каталог `scripts`: запуск использует
`../scripts/run-limited.sh`.

Из каталога `kubuntu-hrtf`:

```bash
sudo apt install python3-venv python3-tk
bash setup.sh
bash launch.sh --check
bash launch.sh
```

Setup устанавливает CPU PyTorch и зависимости из `pyproject.toml` в отдельное
окружение `${XDG_DATA_HOME:-$HOME/.local/share}/3d-audio/venvs/hrtf-pyX.Y`.
Окружение Demucs не обновляется. Для установки нужен интернет; веса ITSADIVE
и базовый SOFA уже включены в исходники. После установки расчёт работает
без сети. Lightning, MATLAB и обучение для запуска не нужны.

Базовый интерпретатор выбирается через `SPATIAL_BASE_PYTHON`, например
`SPATIAL_BASE_PYTHON=/usr/bin/python3.12 bash setup.sh`. Используйте тот же
интерпретатор при запуске. `SPATIAL_PYTHON=/путь/venv/bin/python` позволяет
запускать готовое окружение. Если отдельного HRTF-окружения нет, launcher
может использовать окружение Upmixer; отдельный setup обеспечивает нужные
версии пакетов. Виртуальные окружения создаются заново на каждом компьютере.

Для ярлыка в меню выполните `python3 install-menu.py --install`.
После переноса каталога повторите установку ярлыка.

Launcher выполняет расчёт на CPU с одним вычислительным потоком. Общий
ограничитель разрешает одну тяжёлую операцию, до 210% CPU на трёх доступных
CPU, 3 ГиБ RAM и отключает swap. Не запускайте одновременно сборку Android
или обработку Upmixer. Минимальный процессор и время расчёта не установлены:
они зависят от оборудования. Превышение лимита завершает процесс ошибкой.

## Подготовка профиля

1. Снимите каждое ухо строго сбоку при ровном освещении. Уберите волосы и
   украшения. Разместите линейку рядом с ухом в той же плоскости; оставьте
   поле для квадрата 9,5 × 9,5 см вокруг слухового прохода.
2. Для каждого фото отметьте вход в слуховой проход и два деления линейки.
   Укажите расстояние между делениями в миллиметрах.
3. Проверьте контуры и ориентацию правого уха. Настройте порог, если контуры
   захватывают фон, тени или волосы.
4. Введите ширину головы над ушами и глубину от лба до затылка в сантиметрах.
   Нужны прямые размеры, а не окружность головы.
5. Создайте профиль. Для каждого варианта выбирайте новую выходную папку.

Результат включает `personal.sofa`, `report.json`, `left-contours.png` и
`right-contours.png`. GUI также сохраняет входной manifest и ограниченный
по размеру журнал. Эти файлы могут содержать параметры и пути ваших фото;
проверяйте их перед публикацией. Существующие результаты не перезаписываются.

## Командная строка

```bash
bash launch.sh --cli build /путь/manifest.json --output /путь/новый-профиль
```

Manifest содержит объекты `left` и `right`. Поля каждого: `path`,
`canal: [x, y]`, `reference: [[x1, y1], [x2, y2]]`, `reference_mm`,
`mirror`, `edge_threshold`. В корне задаются `head_width_cm` и
`head_depth_cm`. Координаты относятся к фото после поворота по EXIF, но
до отражения; пути могут быть относительными к manifest.

Вместо параметров фото можно передать `{"contours": "left.png"}`: белые
контуры на чёрном фоне, 256 × 256 пикселей, физический квадрат 9,5 см с
центром в слуховом проходе. Правое изображение должно быть заранее
приведено к канонической ориентации.

## Модели и ограничения метода

Используется [ITSADIVE Hybrid Structural Model](https://github.com/miccio-dk/itsadive_hybrid_structural_model),
commit `e43fbd5c50c1b15e6f1051b72d1f562ed736b8e8`: image encoder и средний
latent VAE, затем DNN и decoder CVAE. Три checkpoint занимают 75 922 584
байта. Их SHA-256 вместе с определением encoder и базовым SOFA проверяются
по `third_party/itsadive/models.json` перед вычислением.

Для каждого уха кодируется отдельное фото. Передняя и задняя срединные
плоскости full-grid модели используются как приближение ушного фильтра.
Влияние головы и корпуса берётся из общего VIKING без ушных раковин;
точного физического разделения головы и уха модель не выполняет.

Акустическая стадия на Python строит минимально-фазовые FIR и добавляет
аналитическую задержку Woodworth по размерам головы. Это адаптация
исходного метода: заменены MATLAB `yulewalk` и выбор ITD измеренного
субъекта HUTUBS. Предсказания ограничиваются −80…+30 дБ. Частотная ось
следует исходной MATLAB-реализации; её физическая калибровка относительно
подготовки обучающих данных требует уточнения.

SOFA использует `SimpleFreeFieldHRIR`: 48 кГц, 729 направлений и два уха.
Длина фильтра учитывает рассчитанные задержки. Они находятся внутри
`Data.IR`, `Data.Delay` равен нулю. Профиль можно импортировать в совместимый SOFA-рендерер, включая
Android-плеер из `android-player`. Качество зависит от снимков и слушателя;
универсальная HRTF может оказаться удачнее. Сравнивайте тембр, высоту и
различение спереди/сзади при одинаковой громкости.

## Проверки и Android-экспорт

Тесты используют синтетические изображения и численные сигналы. Из
`kubuntu-hrtf`, с Python подготовленного окружения:

```bash
bash ../scripts/run-limited.sh env PYTHONPATH="$PWD/src" \
  /путь/hrtf-venv/bin/python -m unittest discover -s tests -v
```

Они проверяют подготовку фото, входные параметры, inference и акустическую
стадию. Это не оценка качества персонализации на слух.

Для пересоздания моделей и эталонов отдельного Android-приложения:

```bash
bash setup.sh --android-export
bash launch.sh --tool ../android-hrtf/tools/export_models.py --help
bash launch.sh --tool ../android-hrtf/tools/export_reference.py --help
```

Описание готовых Android assets и сборки находится в
[`android-hrtf/README.md`](../android-hrtf/README.md).
