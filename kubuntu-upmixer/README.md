# Spatial Upmixer

Локальная подготовка музыки на Kubuntu/Linux: разделение Demucs, расширение
стерео по отдельным дорожкам или создание восьмиканального файла 7.1.
Можно использовать готовые стемы и пропустить нейросеть.

Вход — FLAC, MP3 или Opus, моно/стерео. Выход — Ogg Opus, 48 кГц:
два канала с начальным битрейтом 256 кбит/с либо 7.1 с 512 кбит/с на весь
файл. HRTF в экспорт не добавляется. Для пространственного воспроизведения
7.1 в наушниках нужен совместимый рендерер, например `android-player`.

## Установка и запуск

Нужны Python 3.10+, Tk, FFmpeg с libopus, libsndfile и пользовательский
сеанс systemd с cgroup. Команды выполняются из `kubuntu-upmixer`:

```bash
sudo apt install python3-venv python3-tk ffmpeg libsndfile1
bash setup.sh
bash launch.sh --check
bash launch.sh
```

Setup создаёт изолированное окружение
`${XDG_DATA_HOME:-$HOME/.local/share}/3d-audio/venvs/upmixer-pyX.Y`,
устанавливает CPU PyTorch и Demucs 4.1.0. Установка требует интернета;
веса выбранной модели загружаются при её первом использовании. Последующая
обработка с сохранёнными весами локальная; музыка на сервер не отправляется.
Модели: `htdemucs_ft` по умолчанию, `htdemucs` и `htdemucs_6s`.

Для работы только с готовыми стемами используйте `bash setup.sh --core`:
этот вариант не устанавливает Demucs/PyTorch. `bash launch.sh --check`
проверяет наличие пакетов и FFmpeg/libopus без запуска модели или окна.

Базовый Python можно выбрать через `SPATIAL_BASE_PYTHON`, например
`SPATIAL_BASE_PYTHON=/usr/bin/python3.12 bash setup.sh`; задайте тот же
интерпретатор при запуске. Готовое окружение выбирается так:

```bash
SPATIAL_PYTHON=/полный/путь/venv/bin/python bash launch.sh
```

Сохраняйте соседний каталог `scripts`: оба launcher используют
`../scripts/run-limited.sh`. Виртуальное окружение создаётся отдельно на
каждом компьютере. Исходники загружаются из соседнего `src`, поэтому пути
старой editable-установки не используются.

Ярлык для меню устанавливается командой `python3 install-menu.py --install`.
Повторите её после переноса каталога. Файл `spatial-upmixer.desktop` в
репозитории — шаблон; генератор подставляет текущий путь.

## Обработка и ресурсы

Выберите входной файл, выходной путь и результат — «Стерео по стемам» либо
7.1. Приложение показывает этап, прошедшее время и оценку времени до конца
текущего этапа. Для загрузки модели и операций без измеримого прогресса
оценка может отсутствовать.

Launcher ограничивает одновременно работающую тяжёлую операцию: до 210%
CPU на трёх доступных CPU, 3 ГиБ RAM, без swap. Вычислительные библиотеки
запускаются с одним потоком. Не запускайте параллельно Android-сборку или
HRTF-расчёт. Разделение на CPU может занимать больше длительности записи;
минимальный процессор и гарантированное время обработки не установлены.

**Auto использует CPU.** Для CUDA нужен явный выбор, работающий NVIDIA-драйвер
и совместимое окружение PyTorch/Demucs с поддержкой CUDA. Стандартный setup
устанавливает CPU-вариант. При ошибке выбранной CUDA приложение не переходит
на CPU. FFmpeg, микширование и кодирование остаются на CPU; лимит RAM не
ограничивает VRAM. Использование готовых или кэшированных стемов не запускает
Demucs независимо от выбранного устройства.

## Расширение стерео

Для каждого стема доступны ширина 0–200%, панорама −100…100% и уровень
−60…+6 дБ. Начальный пресет ставит vocals/bass в центр, сохраняет ширину
drums и расширяет сопровождение. «Исходный баланс» задаёт всем стемам
ширину 100%, центральную панораму и 0 дБ.

Ширина изменяется через Mid/Side. Результат собирается по формуле:

```text
output = original + sum(processed_stem - original_stem)
```

Так сохраняется остаток реконструкции Demucs. Нейтральные настройки дают
исходный PCM до общей защиты пиков и Opus. Утечки инструментов между
стемами сохраняются; уменьшение одного стема не гарантирует полного
удаления инструмента. Сильное расширение может подчеркнуть артефакты
разделения. M/S не создаёт ширину из настоящего моно.

```bash
bash launch.sh --cli input.flac wider.opus --output-mode stereo --device cpu
bash launch.sh --cli input.flac neutral.opus --output-mode stereo --stereo-neutral
bash launch.sh --cli input.flac remix.opus --output-mode stereo \
  --stereo-stem other=1.6,0,-1 --stereo-stem guitar=1.3,-0.2,-2
```

CLI использует коэффициент ширины 0…2 и панораму −1…1. Финальная общая
защита уменьшает пики до −2 dBFS; тихий стереофайл не усиливается. Запас
не гарантирует true-peak предел после любого декодера Opus.

## Upmix 7.1

По умолчанию GUI/CLI используют **SurroundUpmix / CenterCutCL**, пресет
Music: три каскада фазового CenterCut, семь основных каналов и LFE с двумя
lowpass 90 Гц. Есть Movie, Anime, PLIIx, базовый `none`, варианты ВЧ-слоя
classic/full и маршруты `4.0`, `5.0`, `mono`, `front`, `rear` для стемов.
PLIIx — название пресета upstream, не лицензированный декодер Dolby.

CenterCut использует FFT 8192, четыре перекрытия, полусэмпловое окно Hann
и выходное Hann². Фазовый коэффициент сохраняет отрицательные значения.
Обработка между стадиями идёт в float64; она не обязана побитово совпадать
с промежуточными PCM-файлами исходного Windows-конвейера. Трёхкаскадная
задержка компенсируется, длительность исходника сохраняется.

Доступен **Мягкий upmix**: спектральный центр вокала, декорреляция
стереоостатков и LFE 120 Гц. Ни один режим не восстанавливает студийный
7.1-мастер из стерео; качество сцены требует прослушивания.

```bash
bash launch.sh --cli input.flac surround.opus --device cpu
bash launch.sh --cli input.flac custom.opus --preset Music --blend full \
  --route vocals=mono --route bass=front
bash launch.sh --cli input.flac soft.opus --upmix soft
```

`--surround-db` по умолчанию 0 дБ для SurroundUpmix и −6 дБ для soft;
`--lfe-db` равен −10 дБ. Каскадный режим нормализует общий пик до −2 dBFS,
в том числе может усиливать тихий файл. Soft только уменьшает пики.
Внутренний порядок PCM — `FL FR FC LFE BL BR SL SR`, FFmpeg преобразует
его в стандартный Opus mapping family 1. Обычный стереоплеер может
воспроизвести downmix вместо виртуальной сцены 7.1.

Источники алгоритма и лицензии CenterCut:
[`third_party/README.md`](third_party/README.md). Оригинальный PowerShell
SurroundUpmix не включён в репозиторий и не требуется для работы.

## Готовые стемы, кэш и файлы

```bash
bash launch.sh --cli input.flac surround.opus --stems /путь/к/стемам
```

Обязательны `bass`, `drums`, `vocals`, `other` в WAV/FLAC; опциональны
`guitar` и `piano`. Они должны относиться к тому же исходнику, начинаться
в той же точке и иметь ту же длительность. Для сохранения баланса подойдут
стемы Demucs, экспортированные с `--float32 --clip-mode none`.

Кэш создаётся в `${XDG_CACHE_HOME:-$HOME/.cache}/spatial-upmixer` или по
`--cache-dir`. Ключ включает содержимое исходника, модель и версию Demucs.
Готовых моделей, музыкальных файлов и кэшей в репозитории нет.

Исходник не заменяется. Существующий выходной файл защищён; замена требует
`--overwrite`. Отмена удаляет временные файлы текущего задания. Промежуточный
PCM занимает около 23 МБ/мин для стерео или 92 МБ/мин для 7.1, дополнительно
к исходному PCM, стемам и кэшу. Для длинных записей требуется свободное место.

## Проверки

Из `kubuntu-upmixer`, с Python подготовленного окружения:

```bash
bash ../scripts/run-limited.sh env PYTHONPATH="$PWD/src" \
  /путь/upmixer-venv/bin/python -m unittest discover -s tests -v
```

Тесты используют синтетические сигналы и реальный FFmpeg/libopus: проверяют
PCM, каналы, длительность, метаданные, отмену, защиту файлов и прогресс.
Независимый численный эталон CenterCut включается отдельно:

```bash
bash ../scripts/run-limited.sh g++ -std=c++17 -O2 \
  tests/centercut_reference.cpp -o /tmp/spatial-centercut-reference
bash ../scripts/run-limited.sh env PYTHONPATH="$PWD/src" \
  CENTER_CUT_REFERENCE=/tmp/spatial-centercut-reference \
  /путь/upmixer-venv/bin/python -m unittest discover -s tests -v
```

Без `CENTER_CUT_REFERENCE` соответствующий тест пропускается. Проверки не
оценивают качество Demucs на музыке и не заменяют проверку CUDA на GPU.
